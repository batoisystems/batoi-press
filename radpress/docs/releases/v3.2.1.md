# Batoi Press 3.2.1

Stable patch release for template-save diagnostics and recovery. PHP remains
8.1+, Batoi Versatile remains 3.3.0 and bundled UIF remains 3.0.0. No database
or content migration is required.

## Changes

- Authenticated template-save requests using a method other than POST receive
  explicit 405/Allow: POST diagnostics instead of a misleading public 404.
  These requests never save a template; authorization remains required.
- Asynchronous template saves reject redirects and unexpected HTML responses,
  report useful status guidance and retain unsaved source for recovery/download.
- Existing POST authentication, CSRF, validation and snapshots remain unchanged.

## Installation and compatibility

Back up first. Stage, review and apply the signed `batoi-press-3.2.1.zip` through
Admin → Updates. Do not unzip starter configuration/content over an existing site.
The updater preserves installation configuration, content and public `.htaccess`.
Bundled default-theme files replace corresponding local customizations; separate
custom themes absent from the package remain untouched.

PHP Sodium remains mandatory for signed updates and must be enabled in the web
PHP runtime, not only the command-line runtime. This release does not bypass
signature verification or fix missing host extensions.

## Verification and limitations

Focused template method/JSON, JavaScript redirect/HTML/405 recovery, smoke,
release-signature and Hosting Health regressions passed, along with syntax checks.
Successful POST recovery behavior remains covered by regression tests.

The original affected-host template-save failure still requires retesting and,
if it persists, matching host request/redirect logs. This patch addresses a
reproducible application diagnostic gap; it does not establish the hosting root
cause. Authenticated browser acceptance was not completed in the latest pass
because the existing testsite login did not establish a session.
