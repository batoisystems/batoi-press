# Batoi Press 3.2.3

Stable compatibility and security-diagnostics patch. PHP remains 8.1+, bundled
UIF remains 3.0.0 and Batoi Versatile remains 3.3.0. No database migration.

## Changes

- Enabled reCAPTCHA integrations receive path-scoped script/connect permissions
  and both documented Google frame sources. Unconfigured sites gain no Google
  permissions; explicit custom CSP policies remain untouched.
- Settings clarify that the built-in contact form uses v2 checkbox keys. Custom
  v3 forms still require their own server-side action/score verification and CSP.
- Partially configured CAPTCHA with only a site key now rejects verification
  instead of bypassing protection. Complete or remove the integration intentionally.
- Contact delivery errors return a neutral message and request reference instead
  of provider details. Private audit records contain correlation, not enquiry data.
- Security diagnostics explain policy precedence, CAPTCHA pairing and the web
  PHP Sodium prerequisite.
- New regression CI, committed-source packaging and signed-artifact verification
  workflows. The release workflow does not deploy the public website; reviewed
  distribution deployment remains separate. No offline signing keys enter CI.

## Update safely

Back up and apply the signed `batoi-press-3.2.3.zip` through Admin → Updates.
PHP Sodium must be enabled in the web runtime. Do not unzip starter data/config
over an existing installation. Configuration, content and public `.htaccess`
are preserved by the updater. Review default-theme customizations before applying;
corresponding bundled theme files may be replaced.

## Verification and boundaries

All 52 standalone PHP entrypoints and JavaScript recovery checks passed locally.
Focused contact/CSP tests also passed on MAMP PHP 8.5.2. Testsite staged-runtime
smoke passed; remote CI results are separate from these local checks.

This patch does not automatically align a custom EHS theme/policy, enable host
extensions, fix unrelated host WAF rules, add built-in v3 support, or complete
Auth0/client acceptance. Proxy hardening, deeper provider-transport testing and
coordinated automated website deployment remain planned work.
