# Batoi Press 3.2.4

Stable contact-mail and integration-policy compatibility patch. PHP remains
8.1+, bundled UIF remains 3.0.0 and Batoi Versatile remains 3.3.0. No database
migration or machine-permission changes.

## Changes

- Contact delivery sends escaped UTF-8 HTML through server mail and Mailgun.
  Visitor markup remains literal text and message line breaks are retained.
  Server mail declares MIME and quoted-printable encoding; Mailgun retains
  its plain-text alternative. Reply-To is validated before either provider runs.
- Mailgun initialization and configuration failures raise controlled delivery
  errors. Failed configuration closes the handle without attempting delivery.
- Settings adds independent opt-ins for Google Maps iframe embeds and
  reCAPTCHA integrated by a custom theme. Maps permissions are limited to
  `/maps/embed` and `/maps/embed/`; they do not enable Maps JavaScript or
  arbitrary Google frames. Disabled sites gain no new Google sources.
- Explicit custom CSP remains authoritative. Private Security diagnostics and
  the existing security guide explain integration ownership and precedence.

## Update safely

Back up and apply the signed `batoi-press-3.2.4.zip` through Admin → Updates.
Enable Sodium in the web PHP runtime. Do not unzip starter configuration or
content over an existing installation. The updater preserves those files and
public `.htaccess`; review any customized bundled default-theme files first.

After updating an affected installation, enable **Allow Google Maps embeds**
only when it uses a Maps iframe. Enable **Allow reCAPTCHA used by a custom
theme** only when that theme independently integrates CAPTCHA. These switches
do not rewrite explicit custom or hosting-injected policies. Custom themes
still own widget rendering and server-side CAPTCHA verification; this release
does not add built-in v3 support or bypass configured built-in verification.

## Verification and boundaries

All 52 standalone PHP entrypoints and JavaScript recovery checks passed locally.
Mail provider-output and failure checks pass without sending email, including
malformed UTF-8, injected reply addresses, rejection, HTTP errors and transport
setup failure. Focused mail tests also pass on MAMP PHP 8.5.2. Testsite HTTPS
policy checks pass in report-only/enforce modes with opt-ins on/off, and its
configuration is restored after acceptance checks. Testsite smoke passes.

Release publication, signed-package installation and remote CI results are
verified separately from these pre-release checks. Nartanam browser acceptance,
real mail delivery, authenticated Settings saves, Auth0 setup and actual
Claude/Codex sessions remain distinct gates. This release does not update a
production installation automatically or certify those external dependencies.
