# Batoi Press 3.2.0

Backward-compatible reliability and media-performance release. PHP remains 8.1+;
Batoi Versatile remains 3.3.0 and bundled UIF remains 3.0.0. No database or content
migration is required.

## Changes

- Keep recoverable template source after validation, network or hosting errors;
  offer explicit local download and show a safe request correlation ID. Native
  POST preserves whitespace; authentication, CSRF, validation and snapshots remain.
- Stream public assets in bounded memory. Support HEAD, ETag/Last-Modified,
  conditional GET and single byte ranges. Only verified theme fingerprints receive
  immutable caching; cookie/authenticated requests remain private and non-stored.
- Add structured page hero, preload, priority, responsive sizes and optional lazy
  loading. Offer bounded WebP/AVIF derivatives when installed GD encoders support
  them, preserve originals, default optional media preload to none and report
  significant sanitizer removals without allowing arbitrary head markup.
- Add owner/admin Hosting Health for runtime prerequisites, writable directories,
  OPcache, cache policies and explicitly unverified hosting compression.
- Clarify what Cache manages. No rendered-page cache was introduced.
- Preserve customized public `.htaccess` even when an older updater installs this
  release: the file is included for fresh installs but omitted from upgrade targets.

## Installation and compatibility

Back up first. Use the signed `batoi-press-3.2.0.zip` in Admin → Updates; stage,
review and apply. Do not unzip starter config/content over an existing site.
Sodium signature verification remains required. The updater creates a rollback
backup and preserves site configuration, content, users and installation state.

Packaged default-theme files still replace corresponding local default-theme
customizations. Review the backup before upgrading; custom themes outside the
package remain untouched. Retained `.htaccess` files require manual review of
future security/rewrite changes because upgrades no longer replace them.

Image dimensions may affect custom CSS; review layouts and hero placement before
enabling lazy loading or preload. Optional conversion skips unavailable encoders,
large/animated images and insufficient memory. AVIF encoding was not available
on the development host; its fallback was tested. Do not enable duplicate PHP
and hosting compression. Inspect actual headers on the target installation.

## Verification and limitations

50 functional PHP regression scripts passed across the implementation run and
focused reruns, alongside JavaScript recovery tests, PHP syntax checks and Chrome
review. The separate server-only 64 MiB fixture benchmark reduced additional PHP
memory from about 64 MiB to 0.30 MiB. Strong validators add file reading/hashing:
local delivery time increased from about 13 ms to 122 ms, excluding network
transfer. HEAD, 304 and range responses also incur validator work. Local page
renders were about 3–4 ms, so full-page caching was not justified.

The EHS template-save POST/GET discrepancy and 404 remain unconfirmed. This release
improves recovery and diagnostics; it does not claim to fix that hosting-specific
cause. Correlate the request ID, timestamp and sanitized redirect chain with host
logs without disabling security filters or sharing template bodies/credentials.
