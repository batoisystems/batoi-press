# Batoi Press 3.2.2

Stable patch release correcting the default Content Security Policy (CSP)
report-only header. PHP remains 8.1+, Batoi Versatile remains 3.3.0 and bundled
UIF remains 3.0.0. No database or content migration is required.

## Changes

- Generated report-only policies no longer include `upgrade-insecure-requests`,
  which browsers ignore in report-only mode and report as a console warning.
- Enforced HTTPS policies retain the directive. HSTS, inline-script hashes and
  stricter route-specific policies remain unchanged.
- Explicit administrator-defined custom CSP policies are not rewritten. If a
  custom report-only policy includes this directive, remove it from that policy;
  do not enable full CSP enforcement merely to silence the warning.

## Installation and compatibility

Back up first. Stage, review and apply the signed `batoi-press-3.2.2.zip` through
Admin → Updates. Do not unzip starter configuration/content over an existing site.
The updater preserves installation configuration, content and public `.htaccess`.
Bundled default-theme files replace corresponding local customizations; separate
custom themes absent from the package remain untouched.

PHP Sodium remains mandatory for signed updates in the web PHP runtime.
This release does not change host configuration or remove host-level CSP headers.

## Verification

Security-header regressions cover report-only, enforced, disabled and unknown
modes over HTTP, HTTPS and forwarded HTTPS, including HSTS and route-policy
preservation. PHP lint, update-response compatibility, media-proposal and smoke
checks passed. Affected production installations require post-update verification.
