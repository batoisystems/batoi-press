# Batoi Press 2.3.0

This release extends the flat-file publishing workflow and addresses the revised Batoi Test Team backlog. Existing posts retain their `/blog` URLs unless their type is explicitly changed. The bundled default theme is Batoi Versatile 3.2.0; the bundled UIF remains 3.0.0.

## Changes

- Add post types such as News and Activities with dedicated archive/detail URLs, same-type parent/child hierarchies, collision checks, API support, and static archives.
- Add per-block featured-image, publication-date, and Read more controls.
- Add opt-in Load More with ordinary pagination fallback, a visitor light/dark switch, validated per-mode color settings, footer grids/text/icon links, and scroll-to-top.
- Improve gallery configuration, render a current-month activity calendar, and support provider-hosted newsletter signup links without collecting subscriber data in Press.
- Add authenticated OpenSSL AES-256-GCM secret storage when Sodium is unavailable, while preserving existing Sodium-encrypted secrets.
- Replace the missing-Sodium update-check crash with actionable setup guidance. Signed updates still require Sodium; signature verification is never bypassed.
- Improve native XML format guidance and embedded-media reference mapping, including post type, publication date, and featured-image metadata.

## Compatibility and verification

PHP 8.1+ is supported. Appearance enhancements require the bundled default theme or equivalent custom-theme integration. Existing v1 encrypted secrets still require Sodium to decrypt. Back up content, configuration, and encryption keys before upgrading. Changing post types changes public URLs; redirect migration is not automatic.

All 35 PHP regression scripts passed, including smoke, signature, update-runner, routing, import, widget, and export checks. Secret storage and Settings persistence were also tested with Sodium functions disabled. Chrome synthetic-content checks covered custom routes, Load More completion, theme preference persistence, and calendar rendering.

## Known limits and open acceptance checks

- The importer accepts native Batoi Press XML, not arbitrary XML, WordPress exports, or sitemap files. The team's rejected XML sample is still needed. Remote media is not downloaded; CSS/srcset references are not rewritten. Imports are additive and not transactional.
- Live-host template-save 404 reports still require deployment-specific request/server or WAF logs. Do not disable hosting security to work around them.
- The affected Windows/macOS package-application reports require a fresh signed-package test on those installations. Local path and rollback regressions are not evidence of every hosting environment.
- Newsletter signup is a link to an explicitly configured provider page, not a campaign sender or local subscriber database.
