# Batoi Press 3.1.0

Stable, backward-compatible feature and reliability release. Default theme: 3.3.0. Bundled Batoi UIF: 3.0.0. PHP requirement remains 8.1+. No SQL migration is required.

## Changes

- Move individual pages/posts to recoverable Trash and restore privately as drafts. Revision, CSRF, ownership, homepage and parent safeguards remain enforced; no permanent purge is introduced.
- Edit ten OG/Twitter metadata fields with validated persistence and escaped default-theme rendering.
- Use safe UIF icon tokens such as `uif:rss-feed` in footer icon links while retaining visible labels.
- Full-width template source editing, reliable Load More visibility and final-page removal, readable default footer contrast, and content-fingerprinted theme asset URLs.
- Safe headers when old/new classes coexist during an in-place update; OPcache invalidation on apply and rollback.
- Clear signed-package prerequisites and optional checksum guidance. macOS web-worker update checks avoid the native post-fork DNS crash without disabling TLS or signature verification.

## Updating and rollback

Back up the installation and test on a non-production copy first. Upload **batoi-press-3.1.0.zip** in Admin → Updates, stage, review diagnostics, and apply. Use the signed release ZIP asset, not GitHub's automatically generated source archive. The updater preserves installation content/configuration and creates a code backup. Do not unzip starter content/configuration over an existing installation.

Customized themes are preserved by the updater. Review and selectively merge the default-theme social metadata, footer, blog, CSS and JavaScript changes into custom themes; never overwrite customer edits blindly. Content fingerprinting refreshes changed theme assets without clearing browser caches manually.

Verify login, public content, update diagnostics, Trash/restore, social tags and blog pagination. Use the recorded update backup for rollback; preserve newer content and credential revocations.

## Verification and limitations

All 47 PHP regression scripts passed in the testing-team follow-up. Real HTTPS testsite acceptance covered page/post Trash and restore, source-template saving, social metadata, UIF icons, Load More, native XML upload and signed update checking. The supplied testing-team XML imported one page and one post successfully; repeat imports skip existing slugs without overwriting.

Hosts must provide Sodium for required Ed25519 verification and the documented PHP extensions. macOS web-worker checks require cURL, direct DNS lookup and a final HTTPS manifest URL without redirects; configured proxies are not bypassed. Other platforms retain normal transport behavior. An affected host's continuing template-save or XML error requires that host's exact response and logs; local acceptance does not certify every hosting environment.

Auth0 tenant configuration, hosted Claude OAuth and complete actual-client workflow acceptance remain separate outstanding integration work. This release does not claim those integrations are configured or certified.
